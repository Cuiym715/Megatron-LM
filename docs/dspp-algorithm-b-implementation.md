# DSPP算法B：当前实现与改进记录

更新：2026-11-01。本文描述g37实际验证并部署的B运行时精简版。代码基点为`d5ea12e079b6dc1ca98497f144728929942013b6`（`cuiym-dspp`），其上有既存未提交工作和本次8文件补丁；**只检出该提交并不包含全部已测实现**。本机文档副本同步本文，不在本次文档维护中同步或覆盖其已有源码改动。实际部署身份及补丁见[证据索引](assets/pp-scheduling/b-runtime-a800-20261101/README.md)。

## 1. 当前算法与运行时

CP 实现与全部实验结果统一见[CP report](dspp-context-parallel-execution-report.md)，下一步见[CP plan](dspp-context-parallel-implementation-plan.md)；下文 A800/PP8 结果仅适用于原 CP1 受控配置。

2026-11-04的D/H tile分派设计、设备首次查询缓存及小规模验证单列于[实现报告增补](dspp-implementation-report.md#2026-11-04增补dh-tile分派与设备配置缓存)：D按FA2共享内存规则选择，H独立保留64×64；A800仍为D64×128/H64×64。本地改动经隔离副本验证，未覆盖服务器运行中任务的源码，不改写下文2026-11-01的训练吞吐记录。

“算法B”指调度求解策略；任务类型`B`指未拆分的stage输入反向，两者不要混淆。给定当前iteration的输入顺序与分块，算法B先生成无拆分供给调度，再选择部分有history依赖的B替换成D/H：D交付完整stage的dx，H计算历史KV梯度。没有history的B不作为拆分候选。W仍是deferred weight-gradient任务。

当前代码保留供给构造、关键路径单拆/配对搜索、H插入位置评分、最多32次接受轮次和soft deadline；没有改成beam/top-k，也没有因本轮输入固定而返回保存计划。真实执行仍由任务依赖、P2P与KV/W状态推进，预测时间只用于规划。

```text
当前轮输入
  -> CPU切分/packing与规则输入排序
  -> 当前轮参考调度、history依赖和任务成本
  -> 后台CPU进程：供给调度 -> B选择性D/H搜索
  -> 按iteration序号接收结果；未及时就绪/失败时使用当前轮参考计划
  -> 各rank材料化当前轮数据并完成必要汇合
  -> 执行F/B/W/D/H、通信及optimizer更新
```

一次只预取一个future iteration；CPU worker不持有CUDA上下文，不在worker中调用训练NCCL。结果仍按iteration、样本位置及microbatch数量路由；去掉内容指纹不等于取消这些执行控制条件。计时实验为在线异步路径，不是同步求解或保存计划回放。

## 2. 时间预测模型与预算

当前取得正收益的是**P实测profile模型**，不是FLOPs模型。按stage/virtual chunk、F/B_fused/W/D/H和实际query/history/packing metadata查询实测成本，使用现有精确shape统计、拟合及允许的插值策略。预测缺失、非有限/非正、外推或不可靠时，现有成本可用性判断仍会限制拆分或回退；这类判断参与求解问题，不是被删除的文件一致性审计。

| 实验名称 | 区别 | 是否用于最新正收益结果 |
| --- | --- | --- |
| P | 原实测成本预测器；进程内固定profile与构建结果 | 是 |
| C | 离线保存紧凑预测器，去掉原始records/分组副本，并按局部shape记忆查询结果；不改变预测公式 | 否，已做对照 |
| F0 | FLOPs乘统一有效吞吐系数 | 否，已做对照 |
| F2 | F/B/W/D/H分别拟合斜率和常数项 | 否，已做对照 |

这四项是成本表示/查询与预测变体，不是四套新的B搜索算法。F0/F2的系数也由既有测量离线标定，启动读取小型系数文件；不能称为完全不依赖profile。C的“紧凑”主要是删掉运行时不再需要的原始记录，保留统计表、拟合系数和覆盖数据。

本批使用`--dspp-planner-backend cpp`和`--dspp-b-budget-fraction 1.0`，未启用旧1000ms固定覆盖。cpp用于现有供给构造后端，B单拆/配对搜索仍在`dspp_plan_b.py`，不是全部求解迁入C++。预算为fraction乘当前参考计划的预测makespan，扣除准备和尾部保留后用于搜索。`1.0`是本批显式实验设置，不宣称修改了函数/CLI的默认预算。精简准备工作可能给搜索留下更多时间，因此同算法也可能在deadline内接受不同数量的拆分。

## 3. 2026-11-01运行时精简：具体改变了什么

本次主要是减少规划前后工程开销，**没有修改`dspp_plan_b.py`的搜索策略、目标、候选顺序或GPU算子**。不能将结果写成“一种新的B算法”，也不能把综合收益单独归因于某一次SHA计算。

| 范围 | 旧路径中的费用 | 当前实现 |
| --- | --- | --- |
| profile快照 | 此前已加入进程内字节缓存，但仍生成内容摘要并核对版本 | 保留快照缓存，取消剩余摘要/版本核验；缓存命中不stat/read/hash |
| 实测预测器 | 重复全context序列化作查询键及模型版本内容遍历 | 固定配置下按(stage, virtual_chunk)+操作查已构建模型；旧紧凑对象在加载时一次转换键 |
| 计划表示 | 反复生成派生tasks/messages、完整指纹、重复解码和图审计 | 最小计划载荷一次导出/解码；兼容性`plan_hash`等字段不再计算内容摘要 |
| 输入身份 | 每轮token内容哈希/JSON往返 | 使用实际样本位置/长度等当前轮元数据，保留iteration和消费位置路由 |
| CPU准备 | 同轮重复排序、构造布局、为尺寸估算再次pickle | 同轮已生成的ordering/counts传给worker和材料化阶段；正常IPC序列化仍执行 |
| 显存模型 | 反复解析JSON、静态layout/schema/floor/范围与实时峰值重审计 | 固定profile一次解析；删除这些重复审计，复用计数结果；实际候选存活量/容量计算保留 |
| 提交执行 | 内容/契约checksum、各rank计划指纹比较、整图重复证明 | 保留typed CPU Gloo汇合与材料化错误传播，不比较内容哈希 |

旧实验hook`DSPP_PLAN_HASH_CACHE=1`仍会为验证缓存命中而遍历/序列化完整计划；`DSPP_SINGLE_VALIDATION=1`仍保留一次发布审计。当前精简版实验将两者均设为0，不在新代码外再套回这些旧包装器。临时`DSPP_FAST_RUNTIME=1`只用于最初隔离验证；8文件部署后已用`DSPP_FAST_RUNTIME=0`及实际仓库模块完成3轮验证，后续对照均走实际源码。

profile文件字节的进程内缓存早于这次全面精简，不能将+2.82%/+3.34%解释为本次才停止每轮重读大文件；本次测得的是删除多处重复工作后的综合在线效果。

首次冷加载的编译器扩展缓存身份及PyTorch/编译系统自身机制未改；它们不属于每轮DSPP内容校验。源码/数据身份在训练计时外记录归档，不能将该归档过程算作热路径开销。

### 3.1 保留了哪些会影响求解质量的计算

- 每轮实际输入生成的分块、packing、排序、history消费者关系与参考计划；
- 当前shape的成本查询、预测可靠性判断、P2P成本及无拆分供给构造；
- B的关键路径、候选评分、真实DAG依赖、每chunk W累加顺序约束；
- 改善候选的owner生命周期/容量可行性计算、搜索内已验证候选缓存及最终token容量/评分一致性判断；
- 预算、迟到/错误回退、材料化错误传播、必要的执行器汇合，以及原有通信/KV/W状态推进。

所以“去掉重复核验”不等于删除所有条件判断或绕过容量约束。用于定义/求解问题的图计算还在，执行完成状态约束也还在；离线全图证明与内容溯源不再每轮重复执行。

### 3.2 缓存的范围与真实变长数据

缓存的是固定profile、预测器/静态系数，以及**同一轮**已经生成的元数据。没有将`16×2K+1×16K`对应的最终调度硬编码，没有跨轮直接取一个保存的完整B计划，也没有在新shape下直接套用2K的执行时间。

输入shape变化时，下一轮重新取数据、生成metadata与参考调度，并提交B求解。相同局部shape可以复用成本统计，不能据此跳过当前轮依赖与容量建模。

当前快照以“一次训练固定模型/分层/精度/kernel/profile”为前提：预测器用(stage, chunk)简化键，不支持在同一实例中混用不同模型/kernel context。替换profile文件内容不会热更新，需重启；换模型、分层、chunk、kernel或扩大长度范围时，在准备阶段选择/补齐匹配的计算/P2P/显存profile并验证适用性。重复的配置匹配和显存覆盖范围审计已删除，不依赖runtime自动发现选错文件；预测器本身的缺失/外推判断仍保留。

本批benchmark入口包含固定模型/有效token数等实验断言，只用于这组受控比较；真实数据测试应使用相应训练入口/统计口径，不能把benchmark的固定配置断言当作B核心的通用输入接口。

这些工程优化不要求每轮输入shape相同；但当前性能结论只验证了受控输入，**未完成真实变长数据端到端收益与所有shape的正确性验证**。不能把可泛用的实现思路写成已证实任意真实数据都加速。

## 6. A800/PP8实验与改进记录

所有下列正式项采用每项5预热＋20连续计时，取八rank最长完整更新窗口；包含实际在线准备、求解/发布、通信和optimizer，初始化/编译/最终checkpoint保存单列，不使用详细timeline测量吞吐。共同配置为H2048/FFN5504/MHA16、BF16、padded vocab32128、默认高性能FA、connections32，每更新`16×2K+1×16K`共49152有效tokens；DSPP chunk2048、PP8/VPP2。既有成本profile测于connections2的限制保留，没有伪称全域重新标定32。

### 6.3 同首尾减层规则的三方法复测

每种方法在本轮重新测3次，轮换顺序；没有使用旧吞吐拼接对照。B源码与上一批完全相同，下面的+3.34%是**独立复测结果，不是再次修改算法后的提升**。

## 7. 历史机制、已知错误与尚未验证内容

- [P7历史记录](assets/pp-scheduling/p7-overhead-20261024/README.md)中的“继续读内容计算哈希、提交时全量核验”属于2026-10-24机制，不是当前热路径要求。旧计划/版本/不支持输入的拒绝测试记录保持原样，不能声称删核验后这些旧拒绝测试仍原样成立。
- 首批InfiniPipe61新增验证探针曾错误假设FSDP参数为二维，继而整数linspace端点舍入越界；已改整数arange采样，仅短验证启用。失败未计入性能，未重置GPU、未改原64版算法。
- 最近一轮汇总器曾向所有rank读取仅rank0提供的`valid_tokens`，在baseline已正常exit0后KeyError。修复并复核复用已完成结果，原失败和两版脚本归档，未重跑挑选数据。
- 最近第三次baseline出现单轮2241ms，完整窗口1935.41ms与第二次接近；保留慢轮。现场时钟/功耗快照晚于作业结束，不能用来归因。
- 两次61层B配对都观察到正在线收益，但没有据此进行统计显著性或任意真实数据泛化声明。当前没有精简后64层、真实变长数据多分布、更长序列的完整性能矩阵，也没有新同步/回放矩阵或长期收敛证据。
