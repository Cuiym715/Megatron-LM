# DSPP CP 下一步实验计划

更新：2026-11-06。**后续正式实验全部统一61层；16层、29层数据只作历史结果，不补跑旧模型队列。八卡总计划和profile定时任务均已按用户要求暂停；当前讨论固定chunk4096与数据分配，不启动新实验。** 结果见 [report](dspp-context-parallel-execution-report.md)，实验顺序及对比对象见 [八卡总计划](../../../docs/v5/eight-gpu-master-plan.md)。

## 1. 先取得61层无B端到端基线

- 公共模型：61层、H2048、FFN5504、Q heads16、词表32128、BF16，TP1、样本DP1。比较PP8×CP1与PP4×CP2；第一轮全局chunk2048、同一冻结长短混合输入、相同有效全局token batch。先MHA，不铺开MHA/GQA×全部输入矩阵。
- DSPP PP4×CP2/VPP2已准备的逻辑层数为 `7,8,8,8,8,8,8,6`，物理stage层数为 `13,16,16,16`。stage0同时承担embedding和输出头。首个代表窗口核对端点与中间stage成本；不能用“各卡总FLOPs接近”证明负载均衡，也不能直接沿用PP8的端点平衡结论。若调整布局，在正式profile前冻结，不自动改变总层数。
- 先测已合并通信的KV与当前优化Q/O，两者均关闭D/H及在线B，使用hybrid＋baseline packing；完整更新计时不依赖B的成本profile，因此不等待下节全部完成。固定chunk基线使用相同FA、重计算、预取、优化器和归约设置。
- 正式窗口5次预热、至少20次更新，ABBA至少两对；复用有效窗口。记录有效token吞吐、最慢rank完整更新时间、逐rank allocated/reserved峰值及污染边界。既有数值误差如实披露，不伪称正确性已验收；死锁、NaN/Inf、跳过更新、负载语义错误仍须处理。

## 2. 只补实际候选需要的CP2 profile

本次profile专项固定61层、CP2、MHA和chunk2048，分别补当前KV/QO计算及显存表，共用4MiB PP通信表；未有61层选优结果，不按旧29层结果提前选赢家。不启动无B选优矩阵，不扩GQA、其他chunk或输入全组合。该专项完成后，自动chunk/获选配置+B按总计划后续授权推进。准备阶段一次确认模型、布局、后端、内核与硬件适用性；runtime不增加哈希、全量核验或重复拟合。

| 项目 | 最小补采内容 | 复用与边界 |
| --- | --- | --- |
| 完整stage耗时 | 用两张空闲卡建立真实CP2组，依次加载61层目标PP4实际stage角色，采F、未拆分B、D、H、W。无拆分窗口提供F/B/W，显式拆分窗口补D/H；计算计时关闭owner审计。相同任务取CP两rank耗时最大值，保留端点与中间逻辑stage差异 | 内部CP通信已包含在任务耗时中，不另要求CP带宽全扫描。输入hidden states/dout在计时前准备，真实history依赖与deferred W保留；注明两卡隔离采样不含并发PP竞争，不改名冒充八卡在线耗时。只采候选实际触及的Q长度、history、packing与chunk形状；保留重复样本，不扫描无关组合。旧小模型时间不能直接乘层数替代 |
| 调度显存模型 | 用两卡上目标物理stage的独立无拆分/非空D/H短窗口，两个VPP chunk常驻状态须同时保留或显式解析计入；确定训练常驻基线、按生命周期保留的激活/历史KV/前缀/pending dKV/H及W输入、临时workspace；去重共享storage，按CP最重rank建立系数/解析下限 | 29层owner证据可复用分类与工具，不能把原峰值当61层预算。只取更新/修正模型所需状态；不用为每条候选调度重跑显存profile。八卡完整流水线的并发workspace/整卡峰值另作短验证，不作为两卡分项采样前置 |
| PP点对点通信 | H2048、全局chunk2048、CP2、BF16时，每条CP lane消息为 `1024×2048×2=4 MiB`；用四张空闲卡组成两个CP2组，测实际PP peer、两lane同时通信，复用当前工具的通信与计算重叠口径；记录物理GPU映射，未测目标边保留缺口，不把任意0→1测量冒充全PP4覆盖 | 已核对旧CP2表仅有2 MiB，不能直接覆盖本配置，需补4 MiB。P2P不因层数本身变化重测；如自动chunk候选需要4096，才补8 MiB等实际缺失点 |

为本次固定配置的两条后端生成各自计算/显存文件及共用PP通信文件，检查目标配置实际加载与成本覆盖；两后端的历史缓存、H状态和通信不同，不能相互改名复用。自动chunk只补其实际候选集合的成本缺口。CP1已有61层表另按现有准备流程核对，不因新增CP2而整套重采。

## 3. 对获选配置检查D/H并测在线B

- 用61层目标输入做包含实际非空H的短完整更新对照，复用已有小模型算子和发布/回退验证。显式计划或理论时间可用于功能检查；正式B性能使用上节实测成本，不把模拟时间当性能依据。
- PP4×CP2最多四种DSPP配置：KV固定2048无B、Q/O固定2048无B、获选路线自动chunk无B、前三者最佳配置＋B。PP8最多固定/自动两种无B配置和最佳配置＋B。不新增四组KV/QO×模板/B全组合。
- B与其对应无B配置配对；计入实际在线规划、等待和回退，记录真实拆分数、H跨任务延后、dx交付、峰值及吞吐。零拆分/负收益保留；完整更新跑通不等于数值通过。

## 4. 后续性能优化与容量实验

- 首版端到端表完成后，再按瓶颈做CP通信、FA、组装/拷贝、PP等待的独立诊断和少量长度容量点；不把整套容量扫点作为首版前置。每项调优后测受影响部分，有局部收益再复测端到端，保留改动前基线。
- 短尾、真实arXiv、GQA、更多长度按实际缺口补，继续使用61层。可选cp-aware、前缀重建、在线CP路线选择均不是现成已验收开关，不自动加入本轮。
- CP4与CP3扩展不属于本轮必做项；若之后启用，先补相应并行度功能检查，正式模型仍为61层，不搬用旧16层结果代替。

- 本机和g37保护现有源码，沿用tinacui-megatron、现有venv/数据/兼容扩展缓存，独立输出目录；不commit/push。只做必要命令与配置预检，不重复全量审计。
- profile专项也已按用户最新要求暂停，其他总计划/单卡定时任务继续暂停；后续须用户明确恢复。以下资源规则仅用于恢复后。专项进度写 [profile检查点](assets/cp/profile61-checkpoint.json)，每5分钟检查：有两张空闲卡即推进真实CP2 stage采样，有四张则补PP通信；仅所用GPU要求独占及60秒确认，并记录主机竞争/污染边界，不因其他卡有任务停工。少于两卡先做CPU准备。两卡真实stage入口已部署并通过CPU参数/61层归属预检；GPU功能验证尚未完成。下一次先用新批次运行KV中间stage的fused与D/H对照，再覆盖端点/QO及正式形状；不能把CPU通过当GPU通过。局部采样、导出及目标加载/任务重放验证完成后汇报并暂停，必要PP边缺口继续定点补；八卡整体验证留后续，不扩端到端性能实验。
- 本轮保留已约定的完整BF16 GEMM归约、确定性FA2 backward及exact p0共同设置，明确报告适用边界；不将该结果冒称默认非确定性FA性能。数值排查与正式计时分开。
- profile每进程加载，同轮元数据复用，每轮仍按实际输入求解。结果集中写report，plan只留下一步，资产复用已有目录。
