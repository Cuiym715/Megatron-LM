# P7 续：精简异步计划交接

发布方检查完整依赖图和显存计数，各卡复用同一份参考计划与计数结果。执行前，各卡检查实际输入内容和元数据、配置/profile内容版本、收到的计划摘要以及当前可用显存；发布与提交的两次一致性汇总合并为一次。配置或profile改变时重建本轮备用模板；输入或计划不一致时共同报错，尚未启动计算任务。

默认使用精简路径；`--dspp-prefetch-full-validation`保留原核验路径作诊断和性能对照。同步求解与外部计划保持完整核验。A/B/C搜索、W顺序、D/H算法、kernel、时间/显存预测公式和预算不变。

## 真机对照

沿用P7冻结的seed11分布输入、成本和显存profile；默认注意力模式。模型24层hidden2048/FFN5504/MHA16，BF16、PP3/VPP2、chunk2048、micro4/global8。每组8轮，前2轮预热；后6轮共100,304有效目标tokens，按各rank最长连续墙钟区间计算吞吐，包含输入、计划交接、检查、通信和optimizer。每组一个测量区间。

| 方式 | tokens/s | 相对本轮原模板 |
| --- | ---: | ---: |
| 原融合模板，不启用预取 | 11,341 | 基线 |
| 固定B计划异步回放，原核验路径 | 10,471 | −7.67% |
| 同一B计划异步回放，精简核验 | 11,146 | −1.72% |
| 真实后台求解B，精简核验 | 11,030 | −2.74% |

精简核验的同计划回放比原核验路径提高6.45%。各rank最长发布区间均值57.0→27.9ms，rank0材料化后的提交区间48.9→35.1ms；两段分别记录。完整图和计数工作集中到发布方，其他rank不再重建完整参考图和显存计数对象。

真实后台B的worker均值55.6ms，预热后等待求解0ms；其吞吐比精简回放低1.04%。计算区间均值1393.8/1377.7ms，该区间包含host提交、通信与流水线等待；后台争用与运行波动尚未分离。真实B较本轮原模板仍低2.74%。

B三个对照的每轮实际任务顺序完全一致，均H=0；本轮没有新增含H异步、A/C吞吐或完整梯度/参数对照。各组各rank计划一致、样本位置0–63一致，无非有限loss或optimizer跳步；原通信和KV/H/W排空检查完成。各步实际显存峰值低于冻结计数额度。精简B三卡allocated峰值27.036/23.972/23.899GiB，步末9.051/6.837/6.837GiB稳定。

第一份`fast-replay`记录与检查进程重叠约2.6秒，排除性能统计；只补了一次串行`fast-replay-clean`。正式表格使用后者。

## 保留的改动与PP8测试理由

本轮没有因PP3未显示单项收益而撤回已有改动。逐项吞吐尚未拆测；目前证据不足以认定其在PP8也无效。

| 改动 | PP8值得测试的原因 |
| --- | --- |
| C++供给构造，保留Python对照入口 | 同样输入下，PP增大会增加任务和依赖；就绪队列与事件处理可能更贵。后台求解更快可增加按时产出计划的余地。 |
| 冻结成本覆盖范围预计算 | stage上下文更多，预测调用和重复扫描增加；减少每次预测的固定工作。 |
| 相同计划显存计数缓存 | 更大的图上，参考计划、候选和重复审计的计数成本可能增加；缓存仍用于求解和发布方检查。 |
| 减少计划复制、解码、导出和哈希 | 全局计划随PP与chunk数量增加，减少重复遍历和对象分配的潜在价值增加。 |
| 本轮集中核验、合并汇总 | 减少各rank重复建图和检查，以及一次集体通信；跨机时也值得测量。各卡仍计算收到计划的摘要。 |

现存开销包括发布方解码/结构检查、各卡计划摘要、实际输入绑定、profile内容读取、材料化和实时容量检查。完整CPU输入包仍在轮次边界广播；下一步可单独检查输入传输及后台CPU争用。冷启动沿用原决定，不作为优化目标。
