# 拆分 dQ 确定性隔离诊断（2026-10-24）

已接入可选确定性 dQ；固定B/C计划的三步真机对照全部逐位一致。默认路径仍使用原子累加，之后训练和性能实验统一使用默认模式。

## 实现

`backward_dq(state, deterministic=True)` 与 `backward_dq_current(state, deterministic=True)` 使用固定版本FA2的确定性机制：每CTA一份FP32 dQ分区，按固定跨步遍历KV列，再调用原版 `convert_dQ(params, nsplits)` 固定顺序汇总。分区数为 `ceil(SM数/Q头数)`，每个独立序列batch=1。复用当前/历史KV分块选择，不改H路由、W顺序、通信或调度算法，不改上游header补丁。

Python与native入口均默认 `deterministic=False`。训练attention入口没有新增开关或自动启用逻辑；本轮仅在临时诊断进程里显式开启。确定性scratch为临时workspace，不延长H状态存活；本次实际峰值仍低于原冻结显存额度。常规显存预测器未为诊断模式增加通用计数。

## 少量真机验证

1. 拆分算子检查原问题形状Q2048/K4096、MHA16；另检查非对齐边界GQA、无历史MQA及两序列varlen。确定性重复计算逐位相同，dQ-only与combined-current的dQ相同，current dKV与独立计算相同；融合FA对照仍使用原容差。省略开关/显式False的默认入口也通过原容差检查。
2. 两次训练，各三步：先回放反馈前B计划生成确定性参考，再回放C计划比较。使用原24层、hidden2048/FFN5504/MHA16、BF16、PP3/VPP2、chunk2048、micro4/global8、seed1234、初始LR1e-3；输入仍是已有seed11分布数据，三步共38,888个有效tokens。

B计划来自 `/home/cuiym/tmp/dspp-p5-20261023/seed-reference/seed-{1,2,3}.json`；C来自上一轮 `/home/cuiym/tmp/dspp-p5-continuity-20261024/c-continuous/comparison/iteration{1,2,3}-rank0.json`。计划身份、输入、依赖和显存检查均保留。第一步C确实改变stage1/2编排，后两步保留B；H数1/1/0。使用固定计划隔离数值，不在新kernel上套用旧耗时作在线选择，不用于吞吐结论。

融合FA沿用前轮诊断的确定性设置，仅拆分dQ新增确定性。每个拆分子状态在同一次反向中重复计算两遍，结果都相同。全量输出、dx、参数梯度、logits/loss、更新前后参数复制到CPU，检查有限值并逐张量比较完整字节SHA256；没有抽样或放宽原门槛，也没有保存/比较Adam内部FP32 master/m/v。

## 结论和使用约定

原默认B/C对照的更新参数相对差异2.96%/3.45%/3.66%，在本次确定性设置下变为逐位一致；单算子重复性也恢复。结果支持默认dQ非确定累加导致本例数值轨迹分离，没有发现固定C反馈计划相对B引入额外数值差异。

本次不是确定性拆分与融合B的整轮训练对照，不能据此声称所有历史拆分/融合差异都已解释，也没有评估长期收敛。旧默认模式失败报告保留。之后实验使用默认模式，确定性接口只用于本轮排查。

源码变化会使原时间profile的kernel指纹不再匹配；未改写旧标定身份或测量值。后续在线规划性能实验需重新标定当前默认路径。旧显存额度在本次回放中仍保留硬检查，实际峰值未超限。
