# P2：现有时间预测器与 InfiniPipe 的同数据对比

本轮只做 CPU 离线对比，没有新 GPU 实验，没有更换在线预测器。分支 `cuiym-dspp`，HEAD `9550175c1d14ab309e96f090142e105b1a8501fd`；保留开始前全部改动，未 commit/push。

**结论：这组数据不支持直接换成 InfiniPipe。** 只用相同单序列锚点时，两者前向中位误差接近，InfiniPipe 本地非负版的完整反向更准；双方利用完整测量时，现有预测器的总体中位误差更低。现有模型前向尾部误差仍大，不能据此宣布时间预测已验收。

## 比较条件

- 复用已有24层 hidden2048/FFN5504、MHA16/head_dim128、BF16、PP3/VPP2 的完整 stage CUDA-event 时间线；每个虚拟 stage 4层，embedding/output 所在 stage 独立拟合。capacity 固定2048，输入沿用原性能实验有依据的条件长度分布，详细来源见原 A 性能报告及 `profile-provenance.json`。
- seed11/19 标定，seed29 验证，不跨训练/测试文件。每个物理/虚拟 stage 独立建模，不借用另一个 stage 的 profile。测试每方向1332点，共2664点。
- 比较 F 和 **B+同任务的 W**，不含通信、optimizer、CPU 求解或训练吞吐。原始 F/B/W 按文件、stage、chunk、logical/physical microbatch 一一核对，检查形状相同、无缺失或重复。
- 现有预测器使用当前 P2 的 `extended_features=True` 非负 ridge 核心，保持查表→插值→回归的实际选择顺序。B/W 分别预测再相加，W 按 dense capacity 归一；没有强制每条样本走回归。旧时间线只作为评估输入，没有伪装成具备完整版本身份的生产 v2 profile。
- InfiniPipe 的预测直接执行只读作者源码的 `CostModel.cost_comp`，不套理想 PP 缩放。原二次拟合与本地已有非负拟合分开；后者不是原论文默认实现。

这里的“误差”是逐点 `abs(预测毫秒−实测毫秒)/实测毫秒`，表中给出其中位数和 P95。例如实测20ms、预测22ms，该点误差10%。它不是吞吐下降百分比，也不是训练损失误差。所有非正预测照常计入，不剔除失败点。

## 一：双方只用相同单序列、无历史锚点

训练原始 F/B/W 共2160条，完整 F/B+W 共1440条；每个 stage/op 的有效长度为767/1023/1279/1535/2048。两边得到同一批测量；各方法保留自己的重复测量汇总/拟合方式：现有模型查表取中位数、ridge 使用原始样本，作者锚点二次拟合先按长度取均值。

| 方法 | F误差中位数 / P95 | B+W误差中位数 / P95 |
| --- | ---: | ---: |
| 现有 P2 预测器 | 21.84% / 71.82% | 8.61% / 20.19% |
| InfiniPipe 原无约束二次拟合 | 86.68% / 1012.77% | 43.83% / 589.05% |
| InfiniPipe **本地已有非负拟合** | 22.22% / 72.41% | 5.10% / 19.94% |

原无约束版本仍有 F73、B+W444个非正预测；另两种没有。两种 InfiniPipe 版本的误差与上轮冻结结果一致，已经独立核对。原方法在这组固定 dense capacity、只改变 valid-token 的稀疏迁移锚点上不稳定，不能据此概括论文原生表现。

此时每方向402个测试点形状见过，930个没见过，包括 packed/history；完整的类别差异不能由仅5个首块锚点覆盖。

## 二：双方利用相同的完整已有测量

训练原始 F/B/W 共8316条，对应完整 F/B+W 共5544条。现有模型正常使用查表、插值等机制。

为让简单公式也能使用同样的 packed/history 测量，这里对 InfiniPipe 的三项公式 `a·(Σq²+2hq_first)+b·Σq+c` 用全形状中位数做非负最小二乘，再交给作者 `cost_comp` 预测。**这是本轮明确标记的拟合适配，既不是作者原标定流程，也不是新增运行时实现。** 它没有查表，参数仍只有每方向三个。

| 方法 | F误差中位数 / P95 | B+W误差中位数 / P95 |
| --- | ---: | ---: |
| 现有 P2 预测器 | **8.20% / 75.84%** | **2.32% / 17.77%** |
| InfiniPipe 三项公式＋全测量非负拟合适配 | 19.54% / 108.86% | 3.66% / 20.92% |

每方向1266个测试点形状已见，只有66个完全未见。对这66点，现有模型 F/B+W 中位误差为13.91%/3.57%，简单公式为19.69%/3.82%；F 的 P95分别为112.94%/103.76%，简单公式在这个小子集的尾部略低。**不能把整体8.20%/2.32%称为未知形状精度，或声称现有方法在所有指标都更好。** 各 stage 分组保存在 `summary.json`。

## 现有预测器三条路径分别怎样

下表拆开原始 F/B/W；B 列是执行器内不含 W 的 B，因此和上面完整反向列的数值不同。每格为“样本数；误差中位数 / P95”。

| 训练范围与实际路径 | F | B，不含W | W |
| --- | ---: | ---: | ---: |
| 完整测量：查表 | 1266；8.01% / 74.76% | 1266；2.71% / 36.36% | 1332；2.08% / 33.13% |
| 完整测量：插值 | 66；13.91% / 112.94% | 66；4.85% / 18.31% | 0 |
| 完整测量：回归外推 | 0 | 0 | 0 |
| 仅锚点：查表 | 402；13.12% / 91.80% | 402；3.05% / 43.14% | 1332；2.05% / 33.08% |
| 仅锚点：回归外推 | 930；23.29% / 60.72% | 930；13.18% / 25.31% | 0 |
| 仅锚点：插值 | 0 | 0 | 0 |

这次确实分别统计了路径；没有出现的路径不声称测过。完整测量下回归未触发，仅锚点下才出现大量外推，所以不能把两种训练范围的数字当作同一条件下三算法的独立竞争结果。

查表也会有误差：它取训练记录中同形状的中位时间，验证的是另一次执行的实测时间。这里查表 F 的尾部也大，说明问题不能全归到插值或回归公式；该结果本身不足以判断是 GPU 争用、执行位置、遗漏的上下文还是计时波动。新版生产包装器仍把未验证的非精确区域标低置信，没有因本次离线对比放宽门槛。

## 开销、检查与限制

- 同一 CPU 容器三遍计时中位数：完整测量下，现有核心查询约42.90微秒/完整任务，简单公式约16.71微秒；只用锚点时约40.07与16.54–16.55微秒。现有侧包含 median/P95 两次核心查询及 W 归一，公式一次按原 API 同时返回 F/B。两者都不含元数据准备；现有侧还没有计入 v2 上下文匹配/范围检查，因此这只是明确调用范围的开销参考，不是完整在线模块延迟或训练加速结论。
- 2664条测试记录逐方法重新计算 median/P95，与汇总一致；原始 B/W 对应及相加核对通过；InfiniPipe 公式结果与直接特征计算逐点一致；两种旧 InfiniPipe 基线与上轮冻结指标一致；无训练/测试文件交叉。`git diff --check` 与脚本编译通过。未改生产模型、kernel 或显存代码，无需重新执行 GPU 回归。
- 固定 capacity2048，训练数据形状覆盖较高；没有 D/H、未测 capacity、64K、计划排名或端到端吞吐验收，也不能据此消除先前小模型留出中的问题。

因此继续保留现有预测器。InfiniPipe 的简单公式保留为便宜的基线，不能直接承担当前 D/H 拆分决策；P2 时间精度仍未整体验收。若继续改善，先针对实际前向计时的尾部与上下文做最小检查，不扩大实验矩阵。
