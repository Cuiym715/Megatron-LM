## 改动

- `dspp_plan.py`：复用现有 ready 循环，增加 027 mode 1；分别保持 F/F、B/B 顺序，允许改变 F/B 穿插；最终重建消息 FIFO、依赖和容量检查。A 的 mode 6 接口不变。
- 新增 `dspp_plan_b.py`：迁移 030 cp-all，复用 010/011 的 H 插入位置计算。先遍历当前关键路径的全部单点；没有单点改善时，搜索新暴露关键路径上的配对。保持输入节点顺序、严格改善、最多 32 轮，不加 top-k、beam 或 C 的反馈。
- `dspp_plan_runtime.py`：使用 P2 的真实 stage/P2P 成本和显存计数，D/H 缺少可信成本的任务不参与拆分；成本不可靠则执行原模板。全体先核对同输入参考计划，由组内 rank 0 规划并广播，随后每卡验证最终计划，避免软截止时间产生不同方案。参考构建失败和规划失败均先通过集体通信发布再报错。
- 沿用 031 的完整规划预算 `0.60 × 原不拆计划预测时间`；预扣准备耗时和每计算节点 0.10ms 的收尾预留。最终代码也计入先行参考构建/一致性核对。候选间检查软截止；正在计算的候选及最终校验可能超时，实际超出量写入计划，未实现 P6 隐藏耗时。
- 拆分结束后重新执行真实 Plan 的依赖、FIFO、在途 tokens 和计数式显存审计。不满足预算时整份回退到已经审计的不拆分底座。每个 H 的源任务、消费者及存活期由原 P3/P2 管理。
- 每个 chunk 的 W 累加次序仍固定。027 原优先级不额外加 W/W 边；若生成结果违反执行器的 W 次序，记录 `per-chunk-W-order`，从原模板开始拆分搜索。这是当前部署约束，可能损失收益。

## 少量定向验证

84 项已有 CPU 回归和 8 项 B 检查通过（日志有重叠，不相加成实验组数）。B 检查包含 PP4/8 真正选中拆分、依赖/FIFO 与有限 credit、精确插入评分、只有配对才改善的例子、零预算/无收益、显存拒绝回退，以及分布式错误发布。

对原研究材料只选 PP4、PP8 各一个案例：

| 输入 | 027 供给底座预测 ms | 030 结束预测 ms | 选中 H |
|---|---:|---:|---:|
| pp4-L8k-extra0 | 374.7792625 | 374.0209744 | 2 |
| pp8-L8kx3-tokenmatch | 734.1106228 | 731.7339501 | 4 |

供给任务顺序与归档结果完全一致；同图、同输入节点编号下，迁移搜索的选点、位置、逐轮 single/pair 类型和最终时间与原始 Python 010/011/030 一致。此对照给搜索 10 秒充足预算，用于查算法迁移，不表示默认 60% 预算下都能搜完，也不是 GPU 加速结果。PP8 这一 CPU 对照本轮搜索约 404ms，说明仍需在真实规模上测规划开销。

迁移初期发现供给顺序不一致。原因是将不拆分时的零耗时 H 依赖节点合并到 B：图的可执行顺序相同，但原算法对“尚未满足的 H”使用参考 B 时间加 stage 漂移作预测，而非运行中 B 的已知结束时间，优先级因此改变。保留该零耗时节点后两个案例一致；诊断和失败日志保留。训练执行不产生这类虚拟 H。

训练共三次，每次三步：融合 B 参考、实测成本 B、构造成本的自动拆分 B。模型/输入复用 P3 的功能夹具：6 层、hidden512、FFN1024、4 heads、head-dim128、BF16、VPP2、capacity64、micro4/global8，合成长度 193/129/33/17，Adam LR 从 1e-3 衰减到 1e-4；完整命令见原始目录。

- 实测成本 B 没有选中拆分，首步因成本覆盖不足回退。该次运行早于上述零 H 节点修正，保留作开发记录，最终验收采用修正后的拆分夹具，不把旧运行当最终版本测量。
- 拆分夹具只替换规划器输入成本以制造有收益的拆分，不改训练算子、依赖、容量或求解器。第二步自动选中 9 个 H，4 个跨其他 B/D/H/W 延后；三卡 F/B 穿插与消息 FIFO 都改变，F/F、B/B 和每 chunk W 次序保持。第三步候选触发显存限制，返回不拆分底座。
